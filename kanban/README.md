# 线程看板（kanban/）操作手册

`kanban/` 用纯文件承载跨会话的笼统目标（称为**线程**）。同一份文件既给人读，也给 Agent 读，无需任何工具，只用文本编辑器即可完成全部操作。OpenSpec change 只是线程可选的关联任务，不是必经路径：小需求一句话记入卷宗即可，是否走 OpenSpec 工作流由你自行决定，Agent 不会默认替你开 change。

## 目录结构

```
kanban/
├── current              # 当前活跃线程的标识（线程目录名）；空或不存在 = 无活跃线程
├── note.md              # 全局便签：仅供人类随手记录，不参与任何工作流（Agent 不读取、不采用）
├── templates/
│   └── thread.md        # 新线程卷宗模板
├── threads/
│   └── <id>-<slug>/
│       └── thread.md    # 每条线程一个目录，内含卷宗
└── README.md            # 本手册
```

## 概念

- **线程（Thread）**：一个笼统目标（如实现某模块、验证某想法）的持久容器，可关联 0:N 个 OpenSpec change，也可以全程不使用 OpenSpec。
- **卷宗（thread.md）**：线程的单一事实来源，记录目标、已完成的工作、决策与（可选的）关联 change。
- **全局便签（note.md）**：`kanban/note.md`，纯人类备忘，不参与工作流——线程解析、状态流转、Agent 校准等动作都不读取它，Agent 也不会采用其中的内容。看板页面头部「便签」按钮可读写，任意文本编辑器也可直接编辑。
- **生命周期四态**：`立项 → 规划 → 实现 → 完成`，全部由你手动流转，系统不做自动推导。

## 操作

### 1. 创建线程

1. 在 `kanban/threads/` 下新建目录，命名规则为 `<id>-<slug>`：`id` 取下一个未用的序号（如 `0002`），`slug` 用线程主题的短横线小写英文（如 `user-auth`），得到如 `kanban/threads/0002-user-auth/`。
2. 复制模板：把 `kanban/templates/thread.md` 复制为该目录下的 `thread.md`。
3. 填写目标：编辑新卷宗，把 `## 目标` 小节下的占位注释替换为这条线程要达成的目标；顺手把第一行 `# <线程标题>` 改为线程标题。
4. 卷宗的 `status` 默认为 `立项`，无需改动。

完成后该卷宗即包含全部必备小节（`status`、`## 目标`、`## 已完成的工作`、`## 决策`、`## Changes`），可直接投入使用。

### 2. 激活线程

把线程目录名写入 `kanban/current`（覆盖整个文件内容，不要多余空格与空行）。例如：

```
0002-user-auth
```

此后新会话的 Agent 会按常驻约定（随 kanban 插件注入）读取该卷宗并与你校准。把 `kanban/current` 清空即可表示"无活跃线程"。同一时刻最多一条活跃线程。

### 3. 手动记录

直接编辑活跃线程的卷宗，向对应小节追加内容（小需求一句话即可，无需关联 change）：

- 完成一段工作 → 在 `## 已完成的工作` 追加一条，注明日期与概要；
- 做出决策 → 在 `## 决策` 追加，每条 MUST 包含"决定了什么"与"为什么"，格式：

```
- **决定**：……
  **原因**：……
```

### 4. 流转状态

编辑卷宗第二行的 `status` 字段，四选一：`立项`、`规划`、`实现`、`完成`。改完即生效，无需其他动作。"目标是否达成"由你判断，不从 change 状态自动推导。

### 5. 关联 change（可选）

仅当你决定使用 OpenSpec 工作流时才需要此步骤。在线程卷宗的 `## Changes` 小节登记 change 名字（仅名字，松耦合引用），一行一条：

```
- add-user-auth
```

属于本线程的 change 归档后，Agent 会把蒸馏总结追加到 `## 已完成的工作`。

## Agent 侧约定（摘要）

完整约定随 kanban 插件分发（插件目录下的 `SYSTEM.md`，经 `systemPromptPath` 注入所有项目会话）：会话开始时会读取 `kanban/current` 指向的卷宗并复述校准；对话出现拐点（方向被否决、想法验证出结论、影响目标的决定、线程搁置/重启）时会询问你是否记入卷宗；归档属于线程的 change 后自动蒸馏追加。约定仅对存在 `kanban/` 目录的项目生效。
