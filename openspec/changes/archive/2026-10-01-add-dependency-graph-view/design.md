# Design

## Context

`add-thread-dependencies` 落地后，列表接口每条线程携带 `deps` 序号投影，小节更新接口对缺失的 `## 依赖` 自动补建。看板前端为无构建链的原生 JS（`viewer/web/`，现有 `detail.js` 等按视图分文件），视图切换已有三视图入口。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 依赖图完全由 `deps` 投影派生渲染，无新增服务端接口、无新增存储。
- 连线即录入：建边/删边复用线程小节更新接口（指纹并发、P4 写路径随之免费获得）。
- 布局自动分层，人工拖拽微调，位置仅存 localStorage。

**Non-Goals:**

- 不做服务端依赖校验（自依赖由前端拦截；闭环仅标记不禁止）。
- 不做依赖关系的反向边编辑（反向边仅由对方 `deps` 派生展示）。
- 不做小地图、缩放平移之外的复杂图编辑（框选、多选、对齐吸附等）。

## Decisions

### D1：纯 SVG 渲染，不引第三方图库

前端无构建链、无依赖管理；图的规模是几十节点量级，手写 SVG（`line`/`path` + 箭头 marker + 分组 `g`）足够，避免引入 dagre/elk 等布局库及其分发问题。备选：引入 dagre 自动布局——层级分配可自己算（D2），为单一算法引入依赖不值得，否决。

### D2：分层布局 = 依赖深度分层 + 层内均匀分布

节点深度 = 到叶子（无出边节点）的最长距离；同层横向均布，层纵向等距，被依赖方（出边指向）在上。环用 DFS 检测：成环节点深度按打破回边后计算并整环标记。布局结果可被 localStorage 中的人工位置覆盖（有则用、无则自动）。key 形如 `kanban-dep-graph:<规范化项目根>:<线程标识>`；项目切换互不污染，`kanban/` 零写入。

### D3：连线交互：拖节点空白处=移动，拖节点连接柄=建边

节点上提供连接柄（如节点边缘圆点），从连接柄拖出临时边，落到目标节点即确认建边；落到自身或空白处取消。建边流程：读 A 详情取指纹 → 在现有 `## 依赖` 净内容末尾追加 `- <B序号>` → 调小节更新接口（缺小节时接口自动补建）→ 重新拉列表刷新图。409 冲突走页面既有「文件已被修改」提示路径。删边：点选边弹出确认，反向操作移除对应行。

### D4：幽灵节点与闭环的呈现

悬空序号渲染为 dashed 边框、半透明、仅显示序号的幽灵节点，入边保留；闭环检测（DFS/Tarjan 均可，规模小用 DFS 足够）命中的节点与边加醒目色标记，hover 提示「依赖成环」。两者都只影响呈现，不触碰数据。

## Risks / Trade-offs

- 自绘 SVG 交互（连线柄、拖拽、碰撞）有一定实现量 → 用既有看板拖拽（卡片换列）的交互实现作参照，控制在小规模节点的最低可用集合。
- 自动分层在稠密/多环图下可读性下降 → 人工拖拽 + localStorage 持久化作为补偿；线程量级小，风险可控。
- localStorage 位置与改 slug 后的线程标识键失配 → 位置键用线程标识（目录名）；改名后旧键成为孤儿但无害，节点回退自动布局。可接受。
- 建边写依赖 `deps` 投影之外的卷宗内容 → 复用小节更新接口（仅替换目标小节、原子写盘），风险与详情页编辑相同，已有规格覆盖。

## Migration Plan

无迁移。前置 change `add-thread-dependencies` 归档后本视图才有数据来源；此前视图可作为空态（无依赖时显示引导文案）。
