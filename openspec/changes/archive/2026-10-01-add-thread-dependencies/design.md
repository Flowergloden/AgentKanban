# Design

## Context

线程卷宗由 `viewer/server/threads.mjs` 的 `parseThread` 通用解析任意 `## 小节`，`updateSection`/`replaceSection` 对任意小节名可写；详情接口的 `sections` 映射天然携带新增小节。前端详情视图 `viewer/web/detail.js` 则以 `SECTIONS` 白名单决定显示哪些小节。Agent 侧行为由插件共享约定正文 `viewer/SYSTEM.md`（Kimi `systemPromptPath`、Codex SessionStart hook 同源注入）承载。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 依赖的唯一落盘形态是卷宗 `## 依赖` 小节的纯序号列表；其余一切（标题、status、摘要、反向边、悬空判定）消费时派生。
- 写路径零新增：建/删依赖复用现有小节更新接口（含指纹并发与 P4 写路径）。
- Agent 校准与推进期间的渐进式、可递归的依赖展开，由约定正文描述，不依赖新接口。

**Non-Goals:**

- 不做状态门控：依赖不约束流转与完成，不做闭环禁止。
- 不做依赖图视图（后续 change `add-dependency-graph-view`）。
- 不做专门的依赖写接口与服务端校验（如自依赖、目标存在性）；非法条目在解析层宽容忽略。

## Decisions

### D1：引用标识用纯序号，不用目录名或 slug

`- 0002` 而非 `- 0002-kanban-board`。重命名接口保持序号不变（`viewer/server/threads.mjs` 的 `rename` 只替换 slug 段），序号因此是唯一稳定标识；用目录名会在每次改名后产生悬空引用。代价是手写时可读性差，由显示层（详情页渲染标题链接）与 Agent 校准（复述序号+标题+status）补偿。备选：目录名引用 + rename 级联改全部依赖方卷宗——引入跨文件写入与 P4 复杂度，否决。

### D2：存储为可选 `## 依赖` 小节，不进 REQUIRED_SECTIONS

`REQUIRED_SECTIONS`（threads.mjs:7）保持四个必备小节不动，存量卷宗不误判「卷宗异常」；`parseThread` 对新小节零改动。备选：frontmatter 字段（如 `deps: [...]`）——偏离「小节即内容」的卷宗结构，且 `replaceSection` 无法直接写，否决。

### D3：条目格式纯序号、无注解，解析宽容

书写格式 `- <四位序号>`。解析规则：小节逐行匹配首位四位序号，合法条目进 `deps`（保持书写顺序、去重），其余行静默忽略。依赖原因不落盘，由消费方以标题/目标摘要支撑推断（spec 见 kanban-threads delta）。序号单调不复用（创建取 `max+1`），删除只产生悬空引用，不产生错指。

### D4：列表投影携带 deps，详情页负责 join

`parseList` 已为每条线程解析卷宗（产出 title/status/goalExcerpt），顺手提取 `deps` 成本为零；详情页渲染 `## 依赖` 时用列表数据做 序号→标题 的 join，悬空序号显示标记。不为详情页新增专用接口。

### D5：约定扩展落在约定一，四条约定结构不变

依赖感知是「会话校准」的自然延伸：约定一增加"复述携带直接依赖 L0 清单（序号+标题+status，悬空标记）"，并描述推进期间的渐进展开阶梯（目标 → 完整卷宗 → 沿链递归，每步按相关性判断，MUST NOT 无条件加载整棵闭包）。不新增第五条约定，两个规格中"四条约定"的表述与 kanban-viewer「插件向所有项目会话注入常驻约定」需求均无需改动；kanban-threads 只修改「Agent 会话启动时读取当前线程」一条需求。

### D6：模板双处同步，注释说明可选语义

`kanban/templates/thread.md` 与 `DEFAULT_THREAD_TEMPLATE`（threads.mjs:29）同步加入 `## 依赖` 小节及注释（可选、纯序号、一行一条）。两者内容必须逐字一致（注释已声明该约束）。

### D7：写路径对 `依赖` 小节缺失自动补建

存量卷宗没有 `## 依赖` 小节，而详情页编辑与后续依赖图连线都要写它。`updateSection`/`replaceSection` 对缺失小节一律报错；本设计为其开一个窄口：仅当目标小节是 `依赖` 且指纹匹配时，在卷宗末尾补建该小节（保持相同空行结构）再写入，其余小节缺失仍报错。备选：新增「补建小节」专用接口——多一条写路径且要复制 P4/指纹逻辑，否决；让前端拼整文件写回——绕过乐观并发，否决。

## Risks / Trade-offs

- 手写格式错误（写成 slug 或带注解）→ 解析层宽容忽略，详情页与列表不报错；错误条目对 Agent 不可见，依赖人读卷宗原文兜底。
- Agent 过度展开撑爆上下文 → 约定明确逐层按相关性判断、禁止无条件加载闭包；L0 清单仅序号+标题+status。
- 依赖线程删除后引用悬空 → 显示层标记、校准复述标记，不做级联删除（与"真删无回收站"的既有语义一致）。
- 详情页渲染依赖小节偏离"原文不做渲染加工"→ 规格中为 `## 依赖` 单独开口（仅链接化序号，正文其余原样），是显式的例外而非静默偏差。

## Migration Plan

无迁移：存量卷宗缺 `## 依赖` 即视为无依赖。模板更新只影响此后新建的线程；既有线程需要依赖时手动补加该小节（README 说明）或在详情页编辑。
