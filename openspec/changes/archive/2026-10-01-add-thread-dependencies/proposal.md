# Proposal

## Why

线程目前是彼此孤立的节点：推进某条线程时，与之相关的其他线程的信息（目标、决策、进展）没有任何结构化入口，Agent 与人类都缺少「这条线程还牵涉谁」的导航。需要一个纯逻辑、不约束状态的依赖维度，让推进线程期间可以按相关性渐进式展开其他线程的信息。

## What Changes

- 卷宗新增可选小节 `## 依赖`：一行一个被依赖线程的四位序号（如 `- 0002`），纯序号引用、不附注解；序号在重命名（slug 变化）下保持稳定。依赖只记录关系，MUST NOT 参与状态流转或完成约束。
- 模板 `kanban/templates/thread.md` 与服务端内置默认模板同步加入该可选小节；`kanban/README.md` 补充手动维护依赖的说明。存量卷宗不受影响（`## 依赖` 不进入必备小节校验）。
- 服务端线程列表投影新增 `deps` 字段（解析出的序号列表）；依赖线程的标题、status、目标摘要等元数据由消费方现取现拼，全部不落盘。
- 看板详情页显示 `## 依赖`：序号解析为可点击跳转的标题链接，悬空引用（目标线程不存在）显示删除线式标记；该小节支持与其他小节一致的编辑。
- Agent 常驻约定扩展：会话校准复述活跃线程时携带其直接依赖的 L0 清单（序号+标题+status）；推进线程期间由 Agent 依据标题（必要时目标摘要）自主判断，渐进式展开依赖线程的目标或完整卷宗，可沿依赖链递归展开。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `kanban-threads`: 新增「线程依赖维度」需求（`## 依赖` 小节格式与纯关系语义、模板与文档更新）；修改「Agent 会话启动时读取当前线程」需求，将依赖清单与渐进式展开纳入校准约定（扩展约定一内容，四条约定的结构不变）。
- `kanban-viewer`: 修改线程列表接口需求，投影新增 `deps` 字段；修改线程详情视图需求，`## 依赖` 小节进入显示与编辑范围（序号渲染为标题链接、悬空引用标记）；修改线程小节更新接口需求，`依赖` 小节缺失时由接口在卷宗末尾自动补建（其余小节缺失仍报错）。

## Impact

- 数据/存储：`kanban/threads/*/thread.md` 增可选小节；无迁移，存量卷宗兼容。
- 服务端：`viewer/server/threads.mjs`（`parseList` 投影、`DEFAULT_THREAD_TEMPLATE` 常量）。
- 前端：`viewer/web/detail.js`（小节白名单、依赖渲染与跳转）。
- 插件约定：`viewer/SYSTEM.md`（Kimi 与 Codex 共用正文）。
- 文档：`kanban/README.md`。
- 后续 change `add-dependency-graph-view` 将基于 `deps` 投影提供图形化依赖视图（本 change 不包含）。
