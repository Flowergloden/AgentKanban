# Spec Delta

## ADDED Requirements

### Requirement: 线程依赖维度

线程卷宗 SHALL 支持可选小节 `## 依赖`，以纯序号列表记录该线程依赖的其他线程：一行一条，仅含被依赖线程的四位序号（如 `- 0002`）。依赖引用 MUST 仅使用序号，MUST NOT 使用目录名或 slug（slug 可因重命名变化，序号保持稳定）。依赖仅记录关系：MUST NOT 参与线程状态流转、完成约束或任何自动推导；条目 MUST NOT 携带注解或原因说明，依赖原因由消费方结合被依赖线程的标题与目标摘要自行推断。`## 依赖` MUST NOT 进入必备小节校验，缺失该小节的存量卷宗 SHALL 视为无依赖且不构成格式异常。模板 `kanban/templates/thread.md` 与服务端内置默认模板 SHALL 包含该可选小节及填写说明；`kanban/README.md` SHALL 说明依赖的语义与手动维护方式。

#### Scenario: 记录依赖

- **WHEN** 在线程 A 卷宗的 `## 依赖` 中写入一行 `- 0002`
- **THEN** A 依赖线程 `0002`；A 的 status 流转与完成判断不受 `0002` 状态影响

#### Scenario: 重命名后引用保持稳定

- **WHEN** 被依赖线程由 `0002-foo` 重命名为 `0002-bar`
- **THEN** 各依赖方卷宗中的 `- 0002` 无需任何改动，仍指向该线程

#### Scenario: 依赖目标不存在

- **WHEN** `## 依赖` 引用的序号没有对应线程（如目标已删除）
- **THEN** 该引用视为悬空，不影响卷宗解析、校验与其他线程

#### Scenario: 缺少依赖小节的存量卷宗

- **WHEN** 一条既有线程的卷宗没有 `## 依赖` 小节
- **THEN** 该线程视为无依赖，卷宗校验不因缺该小节而报异常

## MODIFIED Requirements

### Requirement: Agent 会话启动时读取当前线程

当 `kanban/current` 指向某条线程时，Agent SHALL 在会话开始阶段读取该线程的卷宗，向用户复述其对当前状态的理解并与用户校准，再开始具体工作。若活跃线程的 slug 精确命中保留标记值 `unnamed-pending`（待命名状态），Agent SHALL 在校准复述前自动完成命名：据卷宗标题（必要时参考 `## 目标` 小节）生成英文 kebab-case slug，并调用看板服务的线程重命名接口完成改名；命名 MUST NOT 询问用户确认，且仅对当前活跃线程执行；命名结果 SHALL 在校准复述中一并报告。校准复述 SHALL 同时携带活跃线程直接依赖的清单（序号、标题、status）；依赖线程的标题、status 与目标摘要等元数据 SHALL 在消费时现取现拼，MUST NOT 复制进依赖方卷宗。推进线程期间，Agent SHALL 依据依赖线程的标题（必要时目标摘要）自主判断相关性并渐进式展开：先读其 `## 目标`，仍不足时再读完整卷宗；被展开线程自身的依赖 SHALL 以同样方式沿链递归展开，每次展开均由 Agent 按当前任务相关性判断，MUST NOT 无条件加载整棵依赖闭包。

#### Scenario: 存在活跃线程

- **WHEN** 用户开启新会话且 `kanban/current` 指向线程 T
- **THEN** Agent 在正式工作前复述线程 T 的目标、当前进展与下一步，并请用户确认或纠正

#### Scenario: 活跃线程处于待命名状态

- **WHEN** 会话开始，且活跃线程的 slug 精确等于 `unnamed-pending`
- **THEN** Agent 先自动据卷宗标题生成英文 kebab-case slug 并调用重命名接口完成命名，随后在校准复述中报告命名结果，全程不询问用户

#### Scenario: 非活跃的待命名线程不处理

- **WHEN** 存在 slug 为 `unnamed-pending` 的线程，但它不是当前活跃线程
- **THEN** Agent 不对其执行命名，留待其被激活后的会话校准处理

#### Scenario: 无活跃线程

- **WHEN** `kanban/current` 为空或不存在
- **THEN** Agent 不执行线程校准，正常工作

#### Scenario: 校准时携带依赖清单

- **WHEN** 活跃线程卷宗的 `## 依赖` 列出若干依赖
- **THEN** 校准复述包含这些依赖线程的序号、标题与 status；悬空引用被明确标记

#### Scenario: 推进期间渐进式展开

- **WHEN** 推进活跃线程时 Agent 判断某依赖线程与当前任务相关
- **THEN** Agent 先读其 `## 目标`，仍不足时再读完整卷宗，而非一次性加载全部依赖线程的卷宗

#### Scenario: 沿依赖链递归展开

- **WHEN** 被展开的依赖线程自身的 `## 依赖` 又指向其他线程
- **THEN** Agent 按同样的相关性判断逐层决定是否继续展开，不无条件加载整棵依赖闭包
