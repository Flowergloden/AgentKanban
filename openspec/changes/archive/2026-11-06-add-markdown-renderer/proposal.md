# Proposal

## Why

看板当前以原始文本展示和编辑 Markdown，用户无法直接阅读格式化内容，也必须手动保存、手动刷新才能看到 Agent 或其他编辑器造成的变更。随着看板成为人机共同编辑的入口，这些行为容易造成内容过时、保存状态不明确和意外冲突，需要一套符合直觉且不会静默覆盖修改的文档交互。

## What Changes

- 为线程详情提供安全 Markdown 阅读渲染，并在线程小节、全局便签和新建线程目标的编辑过程中提供即时预览；Markdown 原文仍是唯一存储格式。
- **BREAKING（交互）**：既有线程小节和全局便签由显式保存改为停止输入后防抖自动保存，展示未保存、保存中、已保存、失败和冲突状态；新建线程目标仍在创建时保存。
- 自动读取其他来源对当前线程、便签和线程列表的修改；页面可见时按指纹轮询，隐藏时暂停，重新可见或获得焦点时立即检查。
- 引入共同基准、本地草稿和外部版本的三方合并：无冲突时自动合并，有冲突时暂停自动保存并提供人工处理入口，不向文件写入冲突标记。
- 保留依赖小节的线程链接与悬空标记，复用现有读写 API、SHA-256 指纹、409、原子写盘和 P4 约束，不引入 CRDT、SSE 或完整编辑器。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `kanban-viewer`: 将线程原文展示和手动编辑约束升级为安全渲染、即时预览、自动保存、外部变更读取与三方冲突处理，同时保持原始 Markdown 存储和现有写盘保障。

## Impact

- 前端：线程详情、便签、新建目标、可见页面数据加载、样式与冲突提示。
- 依赖：vendored Marked、DOMPurify 与 node-diff3；不新增服务端运行依赖或构建时运行要求。
- API 与存储：复用现有接口和 Markdown 文件格式，不新增持久化字段。
- 发布与验证：三种宿主发行包需包含新增运行资源；自动化测试和真实浏览器验收需覆盖安全渲染、连续输入、外部变更、合并冲突及既有功能回归。
