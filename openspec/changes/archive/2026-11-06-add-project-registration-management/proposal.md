# Proposal

## Why

当前注册表把宿主上报的任意 `cwd` 直接视为正式项目，且只增不删，导致 Codex 临时目录和项目子目录长期混入主列表。需要以显式确认规范项目来源，并提供手动管理与忽略能力，同时避免未确认路径触发看板初始化或 VCS 检测。

## What Changes

- 将项目注册划分为「待确认」「已注册」「已忽略」三种持久状态；普通会话启动、心跳及工具活动只能发现待确认项目，不能推翻人工确认或忽略决定。
- **BREAKING**：显式 OpenKanban 代表确认注册；自动发现的新路径不再直接进入正式项目列表。
- **BREAKING**：已注册但没有 `kanban/` 的项目不再随页面加载自动初始化，改由用户显式选择「初始化」或「忽略」；待确认和已忽略路径不得初始化看板或执行 P4 检测。
- Web 增加项目管理入口，支持手动新增、确认、忽略、取消忽略和删除；主项目切换列表只展示已注册项目。
- 删除仅移除注册记录，不删除项目文件；再次自动发现时只回到待确认。忽略则持久抑制后续自动发现。
- 旧注册表条目升级时全部保留为已注册，由用户在 Web 端一次性清理，不依据目录名称或现有文件自动猜测状态。
- 加强项目根路径规范化与手动新增校验，减少路径别名和明显无效目录形成的重复注册。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `kanban-viewer`：修改多项目注册表、看板页面加载/初始化、OpenKanban 确认及项目切换行为，新增注册状态管理与 Web 项目管理要求。

## Impact

- 服务端：注册表数据形状与迁移、注册/活动接口、项目状态管理接口、初始化与 VCS 检测门控。
- 宿主入口：自动活动上报与显式 OpenKanban 的确认语义。
- Web：项目列表、项目管理界面、未初始化项目选择、当前项目删除或忽略后的导航。
- 测试：注册状态流转、旧数据迁移、持久化、自动发现幂等、忽略抑制、显式确认、初始化门控及页面交互。
- 不引入新的外部依赖，不涉及项目文件删除或 P4 submit。
