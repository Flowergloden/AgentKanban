# Design

## Context

现有前端采用 vendored Preact + htm，无运行时构建步骤。便签和线程小节以 `createDocumentSync` 维护原文草稿、共同基准与指纹，新建目标仅维护本地 `goal`；三者均通过受控 `textarea` 输入，并用 `MarkdownPreview` 将整段原文经 Marked + DOMPurify 渲染到独立区域。外部更新已经具备三方合并与冲突暂停语义，线程详情另用 `mapCursor` 修复 textarea 选区。

新编辑表面必须继续接受任意外部编辑器直接写文件，不能假设所有写者共享结构化文档或编辑器历史。静态发行还要求依赖自包含、无 CDN、无需用户执行 npm install，并纳入精确资源白名单。

## Goals / Non-Goals

**Goals:**

- 用源码编辑器事务和视觉装饰实现 Live Preview，编辑文档始终与 Markdown 草稿一致。
- 将用户输入、任务点击、外部合并和源码模式统一为原文变更，避免内容转换与编辑器重建。
- 复用现有安全渲染和文档同步内核，保持静态发布、回退与冲突界面可用。
- 让渲染更新按可见区块和实际变化执行，避免每次按键重建整篇预览。

**Non-Goals:**

- 不采用 ProseMirror 一类结构化富文本文档作为事实来源，不实现 HTML/富文本到 Markdown 的序列化。
- 不追求完整 Typora 功能、工具栏、多人协同、CRDT 或在线光标。
- 不改变服务端 API、文件格式、自动保存时序、轮询协议或冲突合并规则。
- 不允许未清理 HTML 因编辑器 widget 获得新的绕过路径。

## Decisions

### 1. 以 CodeMirror 6 持有唯一原文文档

新增共享 `MarkdownLiveEditor` 组件，以 `value`、`onChange`、样式和聚焦选项适配三个调用方。组件内部挂载一个 `EditorView`，其 `Text` 文档就是 Markdown 原文；Preact 只负责生命周期和属性协调，不把渲染 HTML 作为编辑状态。

选择 CodeMirror 6 是因为其文档、选区和变更均以事务表达，语言解析可提供 Markdown 源码范围，且源码模式与 Live Preview 能共享同一文档。完整 Instant Rendering/WYSIWYG 编辑器需要额外验证原文序列化和受控更新语义，结构化富文本方案则不符合原文保真约束；自造 textarea 透明叠加层仍需自行解决选区、IME、块高度和滚动映射，不采用。

### 2. Live Preview 只是可切换的装饰层

使用 Markdown 语法树和选区计算活动编辑单元：

- 非活动区块通过 inline decoration 和 block widget 显示标题、强调、列表、引用、代码、表格等渲染形态。
- 普通段落以物理行、列表以直接列表项为活动编辑单元；代码、表格等复杂结构仍以完整语法块为单位。
- 选区进入编辑单元后，装饰让位于对应原文；离开后按最新原文重建装饰，未选中的连续列表项合并渲染以保留列表上下文。
- 复杂块 widget 携带原文起止范围，禁止通过 DOM 文本反推 Markdown。
- 通过 CodeMirror `Compartment` 在同一 `EditorView` 上启用或停用 Live Preview 扩展，源码模式切换不替换文档、不重建编辑器。

区块 HTML 继续从 `renderMarkdown` 获得，仅当结果为 `ok` 时插入已清理内容。清理组件不可用或渲染异常时停用装饰、显示错误并保留完整源码编辑；`MarkdownPreview` 仍服务只读内容和冲突外部版本。

### 3. 用事务适配受控草稿，区分本地与程序化更新

本地文档事务触发 `onChange(editorDoc)`：便签和线程小节调用 `sync.setDraft()`，新建目标调用 `setGoal()`。父状态回传相同值时不做任何编辑器更新。

当回传值与编辑器文档不同，适配层将其视为程序化草稿变化，以带注解的 CodeMirror transaction 应用最小文本变更并映射选区，禁止销毁后重建 `EditorView`。程序化事务不进入本地撤销历史，并通过更新来源注解避免再次回写形成回声循环；原 textarea 的 `mapCursor` 效果由该适配层取代。

组合输入期间只延迟非必要装饰刷新。若真实浏览器验证表明外部文档事务会中断 IME，适配层 SHALL 暂存最新外部草稿，在 `compositionend` 后以编辑器旧文、当前组合结果和外部草稿执行二次三方合并，再同步合并结果；不得直接覆盖组合内容。

### 4. 任务点击仍由全文档原文定位

渲染任务不作为独立状态。widget 保存其原文区块范围和全文档任务序号，点击后以当前完整原文调用 `toggleMarkdownTask()`，再将返回的新原文送入统一 `onChange`。不得把局部区块内的复选框序号直接当作全文档序号，也不得仅切换 DOM `checked`。

新建目标因此仍只更新 `goal`，便签和线程小节仍进入既有防抖保存、指纹与冲突流程。CRLF、嵌套列表、引用和代码块继续由现有任务定位测试约束。

### 5. 普通入口合一，冲突与只读界面保留分工

- 便签和线程小节仅在普通编辑状态用 `MarkdownLiveEditor` 替换 textarea 与本地预览栏。
- 新建目标用同一组件替换目标 textarea 与预览，但不创建文档同步控制器。
- 冲突状态左侧保留本地 `MarkdownLiveEditor`，右侧继续使用只读 `MarkdownPreview`；既有解决保存、采用外部和关闭前 flush 不变。
- 线程只读小节继续使用 `MarkdownPreview`，`## 依赖` 只读专用链接组件不变。
- 保存状态、完成编辑、错误横幅及自动聚焦保留在原入口层，不塞入编辑器内部重复实现。

### 6. 以自包含 ESM bundle 发布固定编辑器依赖

将固定版本 CodeMirror 6、Markdown 语言支持及必要运行时依赖生成一个自包含浏览器 ESM bundle 并提交到 `viewer/web/vendor/`。生成只发生在开发维护阶段，运行时不打包、不访问 CDN，也不要求用户安装依赖。

`viewer/web/vendor/README.md` 记录 bundle 内容、各包版本、来源、许可证和再生成方式；所有许可证随包发布。`scripts/release.mjs` 增加精确资源项并继续校验运行时 import 闭包，三宿主包包含同一编辑器资源。

### 7. 以视口和变更范围控制渲染成本

语法解析复用编辑器增量状态，装饰计算优先覆盖可见视口；文档变化时仅重建受影响的可见区块，选区变化只调整活动区块装饰。任务切换需要全文档定位时可在点击时解析，不在每次按键执行额外整篇 Marked 渲染。超大文档以真实浏览器测量决定是否需要进一步延迟非可见 widget，而不改变草稿语义。

## Risks / Trade-offs

- [区块装饰边界错误导致光标跳动或原文难以选中] → 活动区块始终暴露原文，复杂表格和围栏代码覆盖进入/离开/跨区块选区测试，并保留一键源码模式。
- [程序化更新干扰撤销历史或中文 IME] → 使用来源注解、选区映射和非历史事务；真实浏览器验证组合输入，必要时按设计执行 compositionend 二次三方合并。
- [局部 widget 的任务序号误定位全文任务] → widget 保存原文范围与全文档序号，复用现有定位函数并增加嵌套、引用、代码块和 CRLF 集成测试。
- [widget 成为新的未清理 HTML 插入点] → 所有 HTML 只能来自 `renderMarkdown` 成功结果，恶意内容在普通预览、编辑 widget 和冲突只读面板分别验收。
- [编辑器 bundle 增大插件及发行闭包] → 固定单一自包含 bundle、记录许可与再生成方式，以三宿主解包校验和运行时 import 校验防止漏文件。
- [大文档装饰渲染成本高] → 使用增量语法树、视口和变更范围更新，补充大文档连续输入与滚动验收。

## Migration Plan

无需数据迁移。按现有静态插件发布流程新增编辑器资源并替换前端界面，服务端与既有 Markdown 文件保持不变。若需回滚，恢复旧前端和发行资源清单即可；期间保存的内容仍是普通 Markdown，无需反向转换。渲染异常时无需回滚即可通过源码模式继续编辑。
