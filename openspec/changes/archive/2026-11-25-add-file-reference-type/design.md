# Design

## Context

当前实现已经由 `schema.mjs`、`field-types.mjs` 和 `thread-document.mjs` 统一承载自定义字段，表格与详情也共用字段更新协议；但非 Markdown/select 的前端分支仍默认落入线程引用控件。服务只有看板文件读写能力，没有系统文件对话框或项目文件正文读取入口，auto 生命周期也只记录最近一次成功活动时间。

项目无构建步骤和第三方运行时依赖，当前打开脚本明确仅支持 Windows。所有字段写入必须继续经过整文件指纹、原子写盘与 P4 门控。`add-thread-document-schema` 已完成但尚未归档，本设计的代码与规格基线包含该 change；开始实施及最终归档本 change 前必须先完成其归档。

## Goals / Non-Goals

**Goals:**

- 用一套规范化与真实路径校验逻辑覆盖手工卷宗、系统选择和只读预览，避免各入口安全语义不一致。
- 将原生进程、文件访问、字段保存和页面草稿解耦，使自动化测试无需弹出真实窗口。
- 复用现有字段更新、冲突处理、模态框与安全 Markdown 渲染，不建立第二套写盘或渲染链路。
- 保持旧项目和未使用 file 类型的项目完全不变。

**Non-Goals:**

- 不使用浏览器 `<input type="file">` 或 File System Access API 推测绝对路径，不支持 Windows 之外的原生选择器。
- 不提供任意项目文件读取、系统默认程序打开、目录选择、文件写入或内容编辑接口。
- 不引入原生 Node 扩展、PowerShell 脚本文件或新的第三方依赖。
- 不为 Markdown 文件预览解析附件，也不在表格或详情加载时预取正文。

## Decisions

### 1. 以独立路径模块统一字段值规范与项目边界

新增 `server/file-paths.mjs`，提供相对路径规范化、项目内路径解析和有界文本读取能力，供 `field-types.mjs`、选择接口和预览接口共同使用。

相对路径规范化先检查原始输入，再统一分隔符：

- 仅接受非空、单行、不含 NUL 的字符串；拒绝 POSIX 绝对路径、Windows 驱动器绝对/相对路径、UNC 路径，以及 `.`、`..` 路径段。
- 将 `\` 转为 `/`，合并重复分隔符，保留中文和内部空格；不以 `path.normalize()` 静默消解越界段，也不接受目录式尾分隔符。
- 类型化值按规范化结果保序去重，序列化固定为 `- <path>`。读取旧卷宗时仅投影合法列表项，非法原文不被读取操作改写；显式更新字段时任一路径非法即拒绝整个值。
- schema 中 file 的 `default` 复用同一校验，未提供时规范化为 `[]`；`required` 在规范化去重后检查非空。`thread-document.mjs` 的空值投影把 file 与 reference 一样初始化为数组，但两者语义保持独立。

实际文件访问同时检查词法路径与真实路径：先确保解析后的候选路径位于项目根，再对项目根和目标执行 `realpath`，利用平台原生 `path.relative` 判断真实目标仍在项目内，并确认目标是普通文件。仅检查 `path.resolve()` 不足以阻止项目内符号链接逃逸，因此不采用该简化方案。保存引用只检查相对路径形式；系统选择与正文预览额外检查实际目标。

### 2. 系统选择只返回候选路径，字段保存仍走既有协议

新增 `POST /api/thread/file-selection`，请求体为 `{ root, id, fieldKey }`。路由复用 `guardSameOriginJson` 和 `requireRegisteredRoot`，并在打开对话框前确认线程存在、schema 字段存在且类型为 file。响应约定：

```text
成功且确认：200 { paths: ["docs/a.md", "src/b.js"] }
用户取消：  200 { paths: [] }
选择无效：  422 { error, rejected: [{ path, reason }] }
```

原生层放入 `server/file-picker.mjs`：以 `spawn` 直接启动 `powershell.exe -NoProfile -NonInteractive -STA`，通过 WinForms `OpenFileDialog` 开启多选。项目根和输出编码等数据经环境变量传入，避免把路径插值进 PowerShell 源码；进程隐藏控制台但显示对话框，stdout 仅承载 UTF-8 JSON 路径数组。非零退出、启动错误、输出过大或 JSON 异常统一变成可读服务错误。

选择结果逐项执行词法与真实路径检查，并收集所有 `rejected`；只要有一项失败就不返回任何可保存的合法子集。选择接口本身不写卷宗，也不接收指纹或新字段值。前端将合法结果合并进草稿后调用既有 `PUT /api/thread/field`，从而保留指纹、409、P4、BOM/EOL 和原子写入行为。相较于“选择接口直接保存”，该方案避免复制并发控制，也明确区分取消、选择失败和保存冲突。

### 3. 预览接口以字段成员资格和真实路径双重收敛读取权限

新增 `GET /api/thread/file?root=...&id=...&fieldKey=...&path=...`，由 `server/file-references.mjs` 编排校验，`server.mjs` 继续负责注册门控和 HTTP 错误映射。处理顺序为：

1. 要求已注册项目、存在的线程、类型为 file 的字段；规范化请求路径并确认它确实存在于该线程该字段的当前类型化值中。
2. 解析项目根与目标真实路径并验证项目包含关系，拒绝目录和其他非普通文件；打开已解析目标，以文件句柄再次确认普通文件。
3. 通过同一句柄有界读取至多 1 MiB + 1 字节，超过 1 MiB 即失败；使用严格 UTF-8 解码并拒绝解码失败或 NUL 内容。
4. 按扩展名返回 `{ path, kind: "markdown" | "text", content }`，仅 `.md` / `.markdown` 归为 Markdown；响应使用 `Cache-Control: no-store`。

字段成员资格使接口不能退化为任意项目文件读取器，真实路径检查阻止符号链接越界，有界读取避免大尺寸文件造成内存压力。接口只返回文本 JSON，不提供静态项目文件服务，也不支持按任意磁盘绝对路径读取。

### 4. 文件 Markdown 预览采用更严格的只读渲染策略

前端新增只读文件预览模态框，点击单条路径时才调用预览接口。Markdown 复用 `MarkdownPreview` 和现有清理失败回退，但文件预览使用禁止图片的渲染策略：Markdown 语法和原始 HTML 中的图片均只显示替代文本，不发起图片请求。普通文本使用 `<pre>` 展示，绝不插入 HTML。

禁止所有图片比仅按 URL 字符串过滤“本地图片”更保守，可覆盖相对路径、`file:`、驱动器、UNC 和原始 HTML 等形式；其代价是文件预览中的外部图片也不显示，不影响看板其他 Markdown 区域的既有渲染。预览不传 `onSourceChange`，任务列表等交互不会转化为写操作。模态框显示加载、缺失、越界、目录、超限和编码错误，并允许关闭后继续处理其他引用。

### 5. 前端使用显式 file 分派与独立草稿控件

新增 `FileFieldControl`，不再让非 Markdown/select 类型默认进入 `ReferenceFieldControl`。表格和详情分别显式分派 markdown、select、reference、file；详情只读模式为 file 渲染路径列表和预览入口，编辑模式提供“选择文件”和逐项移除，不提供文本路径输入。

控件沿用现有 reference 的草稿模式：

- 选择期间设置 busy，禁止重复添加和移除；合法返回后按规范化路径保序合并去重并保存。
- 取消时不动草稿；选择被拒绝或进程失败时展示纯文本错误路径/原因，原字段与草稿不变。
- 保存成功后清 dirty 并刷新；409 时保留包含新选择或移除结果的草稿及明确提示，后续外部刷新不得在 dirty/busy 时覆盖它。
- 预览错误与字段保存错误分区显示，避免预览失败阻断路径增删。

### 6. 用活动租约而非定时心跳保证选择期间服务存活

扩展 `createLifecycle`，增加成对的 `retain()` / `release()` 活动租约；`expired()` 在 auto 且存在未释放租约时返回 false。选择路由在启动原生对话框前取得租约，并在 `finally` 中释放；释放时记录一次活动时间，使用户关闭对话框后获得完整空闲期限。persistent 行为不变，普通请求仍沿用成功响应时活动刷新。

相比选择期间定时调用 `activity()`，租约准确表达“原生操作尚未结束”，无需额外线程或定时器，也能在启动失败、异常输出和进程错误时可靠清理。生命周期测试使用可控时钟覆盖租约嵌套、释放、异常路径和 persistent 兼容性。

### 7. 测试进程边界，真实 UI 只进入 Windows 手工验收

路径规范化和文件读取作为纯/文件系统模块测试；原生选择器通过注入 runner 或测试 shim 模拟 stdout、取消、非零退出和异常输出，CI 不启动真实 WinForms。服务端 API 测试复用 `viewer/test/fixture.mjs` 的临时项目与注册机制，前端静态/行为测试沿用现有 Node 测试方式。

真实系统对话框的初始目录、前台展示、多选、取消、中文与空格路径、混合越界错误以及对话框长时间打开时的服务保活列入 `docs/manual-acceptance.md`。新增服务端和前端运行时文件加入 `scripts/release.mjs` 白名单，并执行三宿主 stage/verify，避免开发目录可用而发布包缺文件。

## Risks / Trade-offs

- [WinForms 对话框可能位于浏览器后方或不同 Windows 会话无法展示] → 使用 STA、隐藏控制台并进行真实 Windows 前台/多选验收；失败时返回错误，不伪报成功。
- [PowerShell 输出编码或大路径列表可能破坏 JSON] → 显式 UTF-8、限制输出大小、只接受结构化 JSON，异常输出不作为路径使用。
- [真实路径检查与打开之间存在本地文件被替换的竞态] → 打开 realpath 解析后的目标并通过同一句柄复检和有界读取；本接口不承诺抵御同用户恶意进程的持续竞态攻击。
- [长期不关闭系统对话框会持续保留 auto 服务] → 将其视为仍在进行的用户操作；所有退出路径用 `finally` 释放租约，persistent 不受影响。
- [禁止文件预览中的所有图片会降低部分 Markdown 的展示完整度] → 以明确替代文本保留内容提示，优先消除本地资源加载绕过；既有看板 Markdown 渲染不受影响。
- [保存时允许缺失路径会留下暂时不可预览的引用] → 这是支持 Agent 先规划后创建文件的有意取舍；预览按当前状态给出明确错误，不自动删除引用。
- [旧版服务无法识别 file schema] → 升级不自动迁移；回滚前按迁移步骤移除 file 配置，不在代码中静默把 file 降级为 reference 或 markdown。

## Migration Plan

1. 在实现和归档本 change 前，先通过既有归档流程完成 `add-thread-document-schema`，以其更新后的主规格作为 delta 应用基线；本 propose 阶段不自动归档。
2. 新版服务只增加类型和接口，不修改默认 schema、现有自定义 schema 或卷宗。项目需要文件引用时显式添加自定义 file 字段；旧卷宗缺字段时仅投影 `[]`，首次保存才补建小节。
3. `protocolVersion` 保持 1：新增接口和字段枚举不破坏既有 API；新版服务按既有版本换代机制替换旧服务，旧消费方不使用 file 时行为不变。
4. 完成自动化、Windows 手工验收、全量测试和三宿主 stage/verify 后再走唯一发布入口，不在本 change 中手工改版本或 tag。
5. 对未使用 file 的项目可直接回滚。已使用 file 的项目先备份 schema 与卷宗，再从 schema 移除 file 字段及对应视图配置后回滚；原文件小节作为普通 Markdown 保留，不执行自动删除或类型转换。
