# 压缩线程卷宗

在保留后续工作所需上下文的前提下，原地精简一份 `thread.md`。压缩的是线程文档，不是当前会话；减少重复和过程性叙述，不把卷宗改写成只反映当前状态的摘要。

## 定位并读取卷宗

1. 以当前会话工作目录为项目根。用户明确指定线程目录或卷宗路径时使用该目标；否则读取 `kanban/current`，以其内容定位 `kanban/threads/<目录名>/thread.md`。
2. 项目没有 `kanban/`、未指定线程且没有活跃线程，或目标卷宗不存在时，说明情况并停止。不要为了压缩而创建目录、模板或卷宗，也不要切换 `kanban/current`。
3. 完整读取目标卷宗后再编辑。不要读取或修改 `kanban/note.md`，也不要为了压缩展开依赖线程或关联 OpenSpec change 的内容。

## 压缩内容

保留原标题、`status`、既有小节及其顺序，包括模板说明和自定义小节。目标和状态不属于压缩范围，除非用户在同一次请求中明确要求修改。

按以下原则整理各小节：

- **已完成的工作**：按同一功能、问题或 change 合并记录。保留日期或日期范围、最终结果、仍有效的重要结论和验证结果；删除重复描述、逐步操作流水、已被后续结果取代的中间状态，以及临时路径、一次性命令等不再有帮助的细节。多项工作不能合理合并时，仍分别保留。
- **决策**：保留仍有效的决定及其原因。合并重复决策；已被取代的决策只保留最新结论和必要原因，早期方案仅在能防止重复探索或解释当前约束时保留。否决过的方向若仍可能影响后续选择，简要保留否决结论与原因。
- **目标与未决事项**：保留未完成工作、限制条件、阻塞因素和继续工作所需的具体标识。不要把计划或未完成事项改写为已完成。
- **Changes、依赖及其他引用**：保留原有 change 名称、线程序号和有效链接，仅去除完全相同的重复项。不要根据名称猜测归档状态，也不要删除看似悬空但未经确认的引用。

无法判断信息是否过时或重复时保留它。不得补写原文没有的日期、结果、决策或验证结论。

## 写入与复核

1. 基于完整原文生成压缩稿，再写回目标 `thread.md`。保留原文件的 BOM 与换行风格，避免无关格式变化。
2. 只修改目标卷宗，不修改其他线程、模板、操作手册、插件约定、代码或 OpenSpec 文件。
3. 写后复核标题、状态和小节是否完整，未决事项与有效决策是否保留，引用是否未被误改，以及是否仍有明显重复。
4. 向用户报告卷宗路径、压缩前后字符数、主要合并或删除的内容类别；有因不确定而保留的信息时一并说明。
